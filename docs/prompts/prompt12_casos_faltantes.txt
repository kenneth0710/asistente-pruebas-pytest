Uno de los cambios no lo detectó ninguna prueba: en _normalizar_para_comparar cambié la condición de la letra de unidad «if len(componente) == 2 and componente[1] == ":":» por «if componente[1:2] == ":":». Con ese error, un archivo de una sola letra con flujo de NTFS, como "a:$DATA", se trata como si fuera una unidad: no se corta desde el ":" y, si la lista de exclusión tiene "a", el archivo se envía a la IA. Según la REGLA 2e, solo una letra de unidad de dos caracteres como "C:" se salva del corte, así que "a:$DATA" debe quedar como "a".

Faltan estos dos casos en la tabla:
- N38 | Partición (nueva) | Nombre de una letra con flujo NTFS no es una unidad | "a:$DATA" | "a"
- E37 | Partición (nueva) | Archivo de una letra con flujo NTFS sigue excluido | "a:$DATA", ["a"] | True
